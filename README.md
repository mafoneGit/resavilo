# Resavilo

Веб-приложение Resavilo на Next.js, React и TypeScript.

## Запуск

Требуется Node.js 20+ и pnpm.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Приложение доступно по адресу http://localhost:3000.

## Production

```sh
pnpm build
pnpm start
```

## Структура

- `app/` — страницы, layout и глобальные стили Next.js.
- `components/` — компоненты интерфейса.
- `hooks/` — React hooks.
- `lib/` — вспомогательные функции.
- `public/` — публичные изображения и иконки.
- `styles/` — дополнительные стили из исходного шаблона.
- `assets/brand/` — оригинал логотипа.
- `archive/` — исходный архив приложения.

## Git

Основная ветка — `master`. Для отдельных задач используйте ветки `feature/<name>` или `fix/<name>`.

Локальные `.env` файлы, зависимости и результаты сборки исключены через `.gitignore`. Секреты не следует добавлять в репозиторий.

## Интерфейс регистрации и входа

- `/` — предпросмотр входа.
- `/register` — предпросмотр регистрации: имя, email, пароль и подтверждение пароля.
- Google, Meta и Apple остаются отключёнными.

Формы проверяют заполнение полей и совпадение паролей. После успешной проверки поля очищаются и появляется сообщение о деморежиме. Аккаунты не создаются, запросы авторизации не отправляются, данные не сохраняются и не логируются. Для просмотра используйте вымышленные данные. CSP блокирует отправку форм, в том числе при недоступном JavaScript.

## Безопасность

Перед включением настоящего входа необходимо подключить серверную авторизацию, проверку прав доступа, ограничение попыток, подтверждение email и сессии с cookies `HttpOnly`, `Secure`, `SameSite`.

Production должен работать через HTTPS. Приложение отправляет HSTS, запрет встраивания во фреймы и CSP с отдельным nonce на каждый ответ. Страницы с nonce не должны кешироваться в CDN. Inline-стили разрешены для текущего дизайна; inline-скрипты без nonce запрещены. При подключении OAuth потребуется пересмотреть `form-action` и разрешённые адреса CSP.

Проверки перед выпуском:

```sh
pnpm audit --audit-level=moderate
pnpm typecheck
pnpm build
pnpm test:security
```

GitHub Actions выполняет эти проверки, Dependabot создаёт обновления зависимостей. Защита ветки и обязательные проверки настраиваются отдельно в GitHub. Архив в `archive/` сохранён для истории и содержит старые зависимости: для запуска используйте только код в корне.

## Resume MVP

Откройте `/resumes` напрямую. Старый адрес `/dashboard` перенаправляет на `/resumes`. Вход и регистрация сохранены как отдельный предпросмотр и не нужны для работы с резюме.

- My Resumes — список, создание, открытие и удаление с подтверждением.
- `/resumes/[id]` — редактор: название, контакты, summary, несколько мест работы, несколько записей образования и навыки.
- Изменения сохраняются кнопкой **Save changes**. При уходе по ссылке с несохранёнными правками появляется предупреждение.

Данные хранятся в localStorage под ключом `resavilo.resumes.v1`, только в этом браузере и origin. Это не облачное хранение: очистка данных сайта или смена браузера удаляет доступ к резюме. Учётные данные туда не записываются.

TypeScript-модель (`lib/resumes/model.ts`) содержит версию схемы, UUID резюме и записей, даты создания/обновления и структурированные секции. Модуль `lib/resumes/storage.ts` отделяет хранение от интерфейса и проверяет структуру, даты и ограничения объёма. Повреждённые данные не перезаписываются; сброс требует подтверждения. Устаревший редактор не может перезаписать более новую версию из другой вкладки. Для MVP поддерживается до 100 резюме; фактический объём ограничен квотой браузера.

Новые зависимости для Resume MVP не добавлялись. Backend, авторизация, AI, импорт и экспорт PDF не реализованы.

В рамках Resume MVP изменены `package.json` (команда тестов), `tsconfig.json` (импорты TypeScript для Node-тестов), `.github/workflows/checks.yml` (проверка модели), `tests/security.test.mjs` (новые маршруты) и этот README. Остальные существовавшие изменения безопасности и интерфейса входа/регистрации сохранены.

Результаты проверки: TypeScript и production-сборка прошли; 16 тестов данных/хранения/предпросмотра и 4 HTTP/security-теста прошли. `pnpm lint` не запускается без ESLint. Визуальная desktop/mobile-проверка осталась невыполненной: браузерный инструмент дважды завершился по тайм-ауту.

Дополнительная проверка: `pnpm test:resumes` (тесты TypeScript-модулей требуют Node.js 24). Существующий `pnpm lint` пока не настроен: ESLint отсутствует в зависимостях. TypeScript и production-сборка проверяются отдельно.

Редактор показывает живой предпросмотр справа на desktop и под формой на небольших экранах. Он использует текущий черновик, включая несохранённые изменения, и показывает только заполненные секции. Для сохранения по-прежнему нужна кнопка Save changes. Предпросмотр — HTML-документ; PDF и разбиение на печатные страницы пока не реализованы.

Следующий предлагаемый этап: пользовательское тестирование редактора и предпросмотра.

## Расширенный шаблон

Контакты дополнены необязательными LinkedIn и portfolio / website URL. При сохранении принимаются полные HTTP(S)-ссылки; поле LinkedIn проверяет домен linkedin.com. Предпросмотр не создаёт исполняемых ссылок из неподходящих протоколов даже во время ввода.

Опыт, образование и сертификаты в предпросмотре идут от последних к более ранним; текущие роли и учёба с датой начала и без даты окончания показываются первыми, записи без дат — последними. В редакторе порядок блоков остаётся стабильным во время ввода. Сортировка не изменяет исходные массивы.

К опыту можно добавлять достижения отдельными пунктами. Существующий свободный текст описаний сохраняется. Дополнительные разделы: языки с пятью описательными уровнями владения (старые CEFR-значения сохраняются); сертификаты с названием, организацией, датой и ссылкой на credential.

Новые поля имеют значения по умолчанию в схеме: ранее сохранённые резюме открываются без сброса данных и получают дополнительные поля при следующем сохранении. Формат localStorage остаётся совместимым с существующим ключом v1. Новый шаблон не является сертификацией совместимости со всеми ATS; PDF-экспорт и проверка распознавания экспортированного файла остаются отдельным этапом.

## Выбор полей в стиле профессионального профиля

Во всех разделах доступны поля с поиском, клавиатурной навигацией и добавлением собственного значения. Локальные списки предлагают языки (в том числе поиск по некоторым родным названиям), навыки, должности, типы занятости и степени образования. Компании, учебные заведения, сертификаты и выдающие организации предлагаются из сохранённых резюме и текущего черновика. Это не поиск по базе LinkedIn и не интеграция с внешним сервисом.

Новые языковые уровни: Elementary proficiency, Limited working proficiency, Professional working proficiency, Full professional proficiency, Native or bilingual proficiency. Названия сверены с официальной документацией LinkedIn: https://learn.microsoft.com/en-us/linkedin/shared/references/fields/languages . Существующие C1, B2 и другие CEFR-значения не пересчитываются: они остаются выбранными с отметкой previous selection, пока пользователь сам не выберет описание.

Опыт работы поддерживает тип занятости и явную отметку текущей роли; образование — текущей учёбы. Новые записи без известной даты окончания не считаются текущими автоматически. Для старых резюме прежнее отображение Present сохраняется до редактирования отметки.

Сертификаты дополнены Credential ID, Expiration date и This credential does not expire. При включении этой отметки дата окончания очищается; при текущей работе/учёбе очищается дата окончания записи. Проверка не допускает окончание сертификата раньше выдачи или одновременно активную отметку и дату окончания.

Даты работы, образования и сертификатов выбираются отдельными списками месяца и года. Неполный выбор остаётся в черновике и требует завершения перед сохранением; дата не подставляется автоматически. Кнопка очистки удаляет обе части даты.
